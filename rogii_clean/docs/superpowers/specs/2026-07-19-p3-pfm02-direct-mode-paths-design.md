# P3-PFM02 三模式路径直接进入 LightGBM：设计说明

## 冻结设计

用户已经批准唯一行为合同：保留 P3B00/P2-P02 原 41 列，只追加 `pf_mode_low_delta`、`pf_mode_middle_delta`、`pf_mode_high_delta`，最终 44 列；模型、1,734 棵树、seed 29、所有参数、fold、目标和评分均不改变。

## 方案比较

1. **独立合法缓存生成器 + 专用训练 runner（采用）**：PF128 与训练目标物理隔离，三列缓存有统一指纹，训练脚本只读取最终三列。代码边界清楚，最容易审计。
2. 修改 PFM01 runner 直接覆盖全部开发井：代码较少，但会把“outer0 诊断”与“全开发集训练特征”混成同一个实验语义，缓存容易误复用。
3. LightGBM 训练时临时读取 PF128 并聚类：少一个磁盘步骤，但训练进程同时持有标签和 PF 原始路径，泄漏边界与中断恢复都更差。

## 数据流

```text
当前井合法输入
  → 冻结 PF128 seed_delta[128, N] + final_ll[128]
  → [整井平均偏移, 末端偏移] Ward K=3
  → scale8 似然加权簇中心
  → 按中心位置命名 low/middle/high
  → 每井三列合法 parquet（不读取 TVT）

B00 原始缓存 + F05a 候选缓存 + P2-P01 五路径
  → P3B00 原 41 列
  → 按 (well_id, row_index) 一对一追加三模式 delta
  → 44 列冻结单模 LightGBM
  → folds 0～1 配对 P3B00 OOF 评分
  → 通过门槛后 folds 2～4
```

## 错误处理与测试

生成阶段必须拒绝缺井、错误 PF128 指纹、非 128 seed、行号错位、影子井、非有限路径和不同模式指纹。训练阶段必须拒绝任何非三列新增特征、错误 41 列顺序、模型参数变化、重复/缺失行键、anchor 不一致、影子井、oracle 字段及缓存不完整。测试先失败后实现，并覆盖 41+3 清单、标签隔离、模式缓存 schema、全开发集合同、合并顺序和训练参数冻结。
