# P3-D01 Task 3：影子隔离、可恢复运行器与真实 smoke

## 本任务只解决什么

把已经审查通过的单井 PF 回放函数接成一个可恢复运行器。它必须先锁定 657 口开发井，逐井只读取合法列，保存 128 个累计似然和合法诊断；然后用旧 P2-P01 合法缓存验证 mean、scale 3/5/8/12 路径逐位一致。

本任务不读取任何目标，不计算 RMSE，不训练模型，不做正式特征输出，也不实现 D01 的相关分析。

## 必须先写的失败测试

1. `load_development_registry(fold_path, shadow_path)`：构造 5 井 fold、2 井 shadow，返回恰好 3 口开发井，且 shadow 交集为 0。
2. `read_legal_inputs(raw_train_dir, well_id)`：水平井返回列严格等于 `MD/Z/GR/TVT_input`，Typewell 返回列严格等于 `TVT/GR`；即使原 CSV 有 `TVT` 和 surface，也不能读入返回表。
3. `generate_one_well(task)`：用 monkeypatch 的小 PF 回放先生成缓存，第二次必须 `cache_hit=True`；改变 fingerprint 后必须重算；runtime 必须写 `hidden_tvt_read=false`、合法列名单和缓存 SHA。
4. 旧缓存路径验证：新回放返回的 8 个路径字段必须和旧合法缓存的对应列按 `row_index` 逐位相等；不等时必须失败，不能只报告差值后继续。
5. 损坏、指纹不符、runtime 缺字段或缓存 SHA 不符不得命中。
6. `run_legal_generation(tasks, workers)` 收集错误；任一错误存在时，调用层不得进入后续评分。

先运行测试确认 RED，再写生产实现直到 GREEN。测试临时目录必须使用项目内唯一 `--basetemp`，不要用系统 `%TEMP%`。

## 注册表和模式

CLI 支持：

- `--mode smoke`：按井号排序后的第一口开发井；
- `--mode fold01`：开发 folds 0 和 1；
- `--mode all`：全部 657 口开发井。

`load_development_registry` 必须：

- 读取固定 fold CSV；
- 兼容 shadow 文件是“只列 shadow 井”或带 `is_shadow`；
- 在任务创建前反连接 shadow；
- 断言井号唯一、fold 只能是 0..4、开发/影子交集为 0；
- 正式配置下断言所有冻结井数和逐折井数/隐藏行数。

## 单井合法生成合同

输入：

- 水平井 CSV 只用 `usecols=["MD", "Z", "GR", "TVT_input"]`
- Typewell CSV 只用 `usecols=["TVT", "GR"]`
- 冻结 P2-P01 `particle_filter` 参数

调用：

- `src.p3_d01_pf_observation_audit.run_pf_likelihood_audit`
- `write_likelihood_cache` / `read_likelihood_cache`

输出到 `artifacts/P3_D01_pf_observation_weight_audit_v1/`：

```text
legal_likelihood_cache/<well_id>.npz
legal_runtime/<well_id>.json
legal/per_well_<mode>.csv
runtime_<mode>.json
```

每井 NPZ 只能有累计 128-seed likelihood 和 fingerprint。每井 runtime 保存井号、fold、hidden_rows、elapsed、cache_hit、输入列、`hidden_tvt_read=false`、完整实验 fingerprint、NPZ SHA、合法 report、与旧缓存每条路径的最大绝对差。

旧合法缓存：`artifacts/P2_P01_multiseed_pf_mean_v1/legal_cache/<well_id>.parquet`。比较字段：

- `row_index`
- `last_visible_tvt`
- `pf128_mean_tvt`
- `pf128_mean_delta`
- `pf128_scale_3_delta`
- `pf128_scale_5_delta`
- `pf128_scale_8_delta`
- `pf128_scale_12_delta`

还要把新 report 的 `pf_best_ll_per_row`、`pf_ll_spread`、`gr_sigma` 与旧 `legal_runtime/<well_id>.json` 对账。正式真实井要求最大差为 0；测试可通过明确 task 标志关闭旧缓存对账，以便使用小型 monkeypatch 数据。

缓存命中必须同时验证 runtime 指纹、井号、fold、hidden_rows、合法列、hidden_tvt_read、文件 SHA、NPZ schema/seed 数和所有旧缓存对账值。任何一项不符就重新计算。

## 并发和失败行为

- 使用 `ThreadPoolExecutor(max_workers=workers)`；Numba 内核会释放 GIL，沿用旧 P2-P01 并发方式。
- 每完成一井打印：完成数/总数、井号、缓存/新算、秒数。
- 每个异常记录井号和错误文本；存在任何错误时主程序非零退出，不能写“已完成”结论。
- 运行可中断；重新执行同一命令时有效缓存必须命中。
- 不要运行 fold01/all。实现者只跑单元测试；真实 smoke 由主代理在独立审查后运行。
