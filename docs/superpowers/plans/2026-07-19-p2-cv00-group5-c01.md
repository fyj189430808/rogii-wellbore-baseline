# P2-CV00 Group5 C01 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development while implementing each behavior. Work directly on the user-requested `codex/phase2-experiments` branch; do not create a worktree and do not commit on the user's behalf.

**Goal:** Keep C01's 36 features and frozen single-LightGBM model unchanged while producing a fully reproducible balanced-well five-fold phase-2 baseline.

**Architecture:** Reuse the existing deterministic fold allocator by making each well its own compatibility `pad_id`. A new runner reads the two frozen C01 caches, replaces the stale phase-1 fold column from the new registry, validates exact coverage, and delegates fold training and metric aggregation to the existing shared LightGBM runner.

**Tech Stack:** Python, pandas, NumPy, LightGBM, pytest, Parquet, JSON.

## Global Constraints

- The only experimental change is `spatial_pad_1000_v1` to `balanced_well_5fold_v1`.
- Keep exactly the existing 36 C01 features and their order.
- Keep exactly the existing `lgbm_feature_baseline_v1` parameter dictionary.
- Keep 773 wells and 3,783,989 hidden evaluation rows.
- Never overwrite phase-1 fold, model, prediction, or metric artifacts.
- Existing numerical caches are read-only; their stale `fold` column must be overwritten by `well_id`.
- All new output lives under `artifacts/P2_CV00_group5_c01_v1/`.
