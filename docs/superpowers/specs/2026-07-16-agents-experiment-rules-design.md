# ROGII 实验协作规则改写说明

## 1. 修改目标

把根目录 `AGENTS.md` 从“先理解和复现 PF，暂时禁止新实验”改成：

> 按 `rogii_clean/experiments/feature_roadmap_v2.md` 完成全部特征实验，在固定单模 LightGBM 下寻找最低且可信的五折 CV。

## 2. 不变的研究边界

- 始终只使用一个 LightGBM。
- 不更换模型，不做模型融合，不加入神经网络。
- LightGBM 参数、树数、预测目标、固定 fold 和评价行保持不变。
- 不恢复同井覆盖，不使用隐藏 TVT、验证井标签或测试时无法获得的信息。
- 主要指标仍为所有隐藏行的 micro RMSE。
- 每个实验仍报告逐折结果、macro、P90、最差井、胜井率和井级配对 bootstrap。

## 3. 新的执行方式

- 以 `feature_roadmap_v2.md` 为唯一实验顺序，先完成 S 系列边际价值，再按晋级结果完成 C 系列条件价值。
- 默认连续推进，不需要用户反复发送“继续”。
- 每个方向先做必要的数据检查或正对照，再进入模型实验。
- 长实验按“1～3井检查 → fold0 → fold1 → 完整五折”推进。
- fold0 未达到门槛就停止当前实现；fold0 通过但 fold1 反向，也停止当前实现。
- 通过前两折后自动运行完整五折。
- 每次只改变一组明确特征，不能同时改变模型、fold、目标或评分方式。
- 正结果和负结果都保存，避免重复尝试已经失败的实现。

## 4. 结果判断

- B00 是固定参考点。
- 当前完整五折最优方案是实验比较对象，但不会替代 B00 的审计作用。
- 新方案只有在相同评价行和相同 fold 下才能比较。
- 小幅提升必须满足路线图中的完整五折、折一致性、P90 和 bootstrap 门槛。
- 负对照或 oracle 与真实实验冲突时，必须降低结论强度。
- 一次实现失败只能否定该实现，不能直接宣布整个信息源无效。

### 4.1 RF01 原结论不得事后改判

- 原 RF01 的八个版本继续按既定门槛判定为“不晋级”。
- 不允许看完更多 folds 后，从八个版本中重新挑一个表现最好的版本。
- 不允许用后续诊断结果追认 RF01 晋级，也不修改当时的停止结论。

### 4.2 独立登记 `RF01_stability_audit_v1`

该实验只用于检查 RF01a 的跨折稳定性，不属于原 RF01 候选筛选。

固定选择 RF01a 的理由提前写死：

- 公式最简单。
- fold 1 损失最小。
- 不含派生程度更高的差值、曲率和无界外推。
- 选择依据不使用 folds 2–4。

固定执行规则：

- 直接复用 RF01a 已完成的 folds 0–1。
- 只补跑 folds 2–4。
- 不改变窗口、特征、LightGBM 参数、fold、目标、评价行或评分代码。
- 不再比较或选择其余七个 RF01 版本。
- 使用独立实验编号、配置和产物目录：`RF01_stability_audit_v1`。

该审计只回答：

> fold 1 是唯一异常折，还是 fold 0 才是异常折？

无论审计结果如何，原 RF01 仍保持“不晋级”。审计结果只能用于理解跨折波动和设计未来的新实验。

## 5. 语言和沟通

- 默认使用中文和普通说法。
- 尽量不用没有必要的英文术语。
- LightGBM、RMSE、CV、文件名、代码变量等无法替代的名称可以保留。
- 第一次出现专业概念时，先说明它实际代表什么。
- 运行长任务前说明运行内容、井数、主要耗时、输出位置和继续方法。
- 运行过程中定期报告进度，但不堆砌没有信息量的状态文字。
- 最终结论区分事实、合理推断、未验证猜测和当前只能否定的实现。

## 6. 工程和留档

- 保留简单、容易阅读的代码结构和中文注释要求。
- 每个实验保存配置、特征列表、参数、预测、逐井指标、运行时间和结论。
- 缓存必须包含完整配置指纹，不能复用来源不明的缓存。
- 不主动执行 Git、worktree、提交、推送或 PR 操作。
- 只有用户要求时才提供 Git 命令；实验本身不等待 Git。
- PF 导读文档继续保留，但不再是运行特征实验的前置门槛。

## 7. 完成标准

只有同时满足以下条件，当前阶段才算完成：

- `feature_roadmap_v2.md` 中每个实验都已完成，或有经过验证的不可运行原因。
- 每个方向都有正对照、关键负对照和清楚的停止结论。
- 所有晋级方案都完成固定五折。
- 已确定当前最低且可信的单模 LightGBM CV。
- 最佳方案能够从固定配置重新运行，并生成一致的预测和指标。
- 最终总结列出最佳特征、失败方向、仍未验证的问题和下一步建议。
- `RF01_stability_audit_v1` 已独立完成 folds 2–4，并与原 RF01 不晋级结论分开记录。

## 8. 明确删除的旧约束

新版 `AGENTS.md` 将删除或改写以下内容：

- “当前唯一目标是理解 PF”。
- “PF 10.7 复现完成前禁止新实验”。
- “必须等用户逐次允许后才能继续实验”。
- 把八份 PF 导读文档作为新研究门槛的规定。
- 与连续执行 `feature_roadmap` 冲突的研究优先级和完成标准。

防泄漏、固定验证、单因素实验、缓存指纹和结果留档规则不会删除。
