# ROGII 全部实验复盘与突破口地图

更新日期：2026-07-17

这份文档按实际代码、配置和 artifact 重新整理，不按实验名字或旧路线图猜测。目标有三个：

1. 从头到尾说明我们真正跑过什么；
2. 说明每个实验改变了哪些特征、取得了什么结果、只能得出什么结论；
3. 判断当前 12.93 与目标 5.0 的差距究竟在哪里，下一步应寻找什么级别的突破。

### 术语边界：两种“同井”不能混为一谈

本文严格区分：

- **训练—测试同井重合 bug**：公榜测试井能在训练集找到同一井号的完整训练副本，历史流程据此读取完整 TVT、surface/contact 并覆盖测试预测。这才是本项目要求去掉的“同井覆盖”；当前干净流程已经关闭并排除该通道。
- **当前井前缀 self-template**：只使用待预测井测试时本来就可见的 TVT_input 前缀和 GR 建立自模板，再匹配该井隐藏段可见 GR。F04 和 sc 系列属于这一类。它不读取训练集中同一口井的完整标签，是合法的测试期前缀自校准，不属于上述 bug。

self-template是否有效，取决于隐藏层位能否被前缀模板覆盖，这是普通的分布泛化问题；不能因为清除训练—测试同井重合 bug 而直接排除F04。

## 1. 先看结论

### 1.1 当前可信成绩

当前最强且可复现的方案是 F05a_deterministic_candidates_v1，也就是后续所称的 C01：

| 项目 | 数值 |
|---|---:|
| pooled micro RMSE | **12.930691** |
| folds 0–4 | 11.708952 / 13.153996 / 13.086706 / 12.337026 / 14.228959 |
| macro well RMSE | 10.150627 |
| median well RMSE | 7.929093 |
| P90 well RMSE | 19.127928 |
| worst well RMSE | 62.962872 |
| 井级胜率（相对 carry） | 69.86% |

它相对简单 LightGBM B00 改善 3.123081 ft，相对 carry-forward 改善 2.979161 ft。五个 fold 都优于 B00，井级 bootstrap 置信区间完全低于零，20/20 个预登记切片全部改善。

### 1.2 真正带来大幅提升的只有一条主线

到目前为止，唯一稳定带来数英尺提升的信息是：

> 把 PF、Beam 等物理候选路径逐行直接交给 LightGBM。

前缀 U 倾角、GR 缺失几何、Typewell 井级可信度、PF 内部统计、伪 holdout、邻井相对 U 等特征，都曾在某些 fold 改善，但没有在 C01 上形成稳定增量。

### 1.3 当前 C01 不是历史所说的“PF 10.7”

当前 C01 使用的是：

- 单次 600 粒子的 ANCC PF；
- 单次 Z PF；
- 7 条 Beam 路径及其均值、中位数、标准差；
- 若干当前井 self-template NCC 路径。

历史 Notebook 另一处 selector PF 则是 500 粒子 × 128 seeds，再做 likelihood/scale 汇总。它尚未在干净项目和固定 spatial-pad CV 中复现，也没有作为 C01 特征正式测试。

当前单独的 pf_ancc_delta RMSE 是 14.2433，并不是 10.7。因此“真正的多 seed selector PF 是否能把当前 CV 明显拉低”仍是一个重要漏项。

### 1.4 已跑 F03b 没有真正测试路线图中的 F03b

路线图要求围绕冻结 PF 路径构造 Typewell 多尺度 offset 得分面。实际代码却围绕恒定 U 路径：

\[
TVT_i^{center}=TVT_{anchor}-(Z_i-Z_{anchor})
\]

在 fold 0 中，真值只有 25.61% 落在该中心的 ±40 ft 搜索窗内；若改成 PF ANCC 中心，覆盖率是 98.53%。所以现有 F03b/N06 的失败不能否定真正的 PF-centered 多尺度局部校正。

### 1.5 到 5.0 不是修几个坏井或再加几个小统计量

从 12.9307 到 5.0，需要消除约 85.1% 的总平方误差。RMSE 大于 20 的 68 口井贡献 51.1% SSE，但即使把这 68 口井全部预测完美，整体仍约为 8.96。若只靠“完美修复最坏井”，约需修复 286/773 口井才能达到 5。

这说明差距是广泛的路径偏差，而不是少量离群井。

## 2. 结果口径和证据等级

固定主合同：

- CV：spatial_pad_1000_v1；
- 773 口井，3,783,989 个自然隐藏评价行；
- target：TVT - last_known_TVT；
- 单个固定参数 LightGBM，1,734 棵树，seed 29；
- 不使用 outer-valid early stopping；
- 不改变评价行、target、fold、模型和后处理。

本文使用以下证据标签：

| 标签 | 含义 |
|---|---|
| 5F | 完整固定五折，可作为正式 CV 证据 |
| EXTRA-5F | artifact 有五折，但原实验按门槛未晋级，额外结果不能事后改判 |
| 2F-SCREEN | 只跑 folds 0–1，用于筛查实现 |
| 1F-SCREEN | 只跑 fold 0 |
| DIAG | 不训练正式模型的合法诊断 |
| ORACLE | 使用隐藏真值，只说明表示能力或上限，不能提交 |
| LEGACY | 旧 CV、旧缓存或旧报告，与当前固定 CV 不直接可比 |

统一记号：

\[
改善 = 同折基线RMSE - 实验RMSE
\]

正数表示更好。F01–F07 默认相对 B00；N01–N06 默认相对 C01。

## 4. 基线实验

### 4.1 CV00_carry_forward_v1

方法：所有隐藏行都预测为本井最后一个可见 TVT_input。

\[
\widehat{TVT}_i=TVT_{last\ visible}
\]

五折：13.7440 / 16.2169 / 15.7325 / 16.7932 / 16.8593；pooled 15.909853。

它不使用模型，是所有实验必须超过的最低对照。

### 4.2 B00_simple_lgbm_v1

实际只有 12 列，而不是路线图文字所说的“已有 PF/Beam/Typewell”：

| 类别 | 特征 |
|---|---|
| 锚点 | last_visible_tvt |
| 隐藏进度 | md_since_visible_end, hidden_fraction |
| 当前坐标 | x_current, y_current, z_current |
| 相对可见端 | dx, dy, dz, dxy_from_visible_end |
| GR | gr_raw, gr_missing |

五折 pooled 16.053772，比 carry 差 0.143919。说明仅靠当前 XYZ、进度和原始 GR，固定 LightGBM 不能可靠恢复未来 TVT 路径。

重要文档偏差：路线图中的 B0 被写成包含冻结 PF/Beam，实际 B00 完全没有。F05a 相对 B00 的 3.12 ft 提升，实际上包含了“第一次把物理路径加入模型”的全部收益。

## 5. 第一轮：可见前缀 U 倾角

统一定义：

\[
U=TVT_{input}+Z
\]

这一组假设地层结构 U 的可见前缀倾角能够外推未来结构走势。

| 实验 | 新增方法和特征 | fold 0（改善） | fold 1（改善） | 结论 |
|---|---|---:|---:|---|

| F01b_prefix_u_stats | 删除3列无界外推，保留 slope、fit RMSE、短长窗差，共7列 | 14.2466 (+2.4298) | 14.6925 (-0.4054) | 井级统计仍反向 |
| F01c_gated_projection | 仅在未来1000 ft内启用三种线性外推，远处置NaN | 14.4058 (+2.2706) | 14.3985 (-0.1113) | 门控减轻但未消除反向 |
| F02_prefix_u_stability | 加100-500坡差、50ft分块坡度std、正坡比例、最大坡度跳变，共6列 | 14.5673 (+2.1091) | 15.0247 (-0.7375) | 固定窗口稳定性不足 |
| F02a_u_slope_std500 | 只加最近500ft分块坡度std | 14.5566 (+2.1197) | 14.6007 (-0.3135) | 单列仍不稳 |

这组最有价值的诊断不是模型分数，而是外推失效：

- 可见前缀内部伪 holdout：carry 约 8.66，最近 200 ft 倾角外推约 3.68；
- 自然长隐藏段：200/500/1000 ft 线性外推分别约 43.42 / 39.36 / 42.29。

因此“前缀短期走势可预测”不等于“未来数千英尺结构保持同一坡度”。

当前只能否定：固定窗口坡度的直接长距离外推。不能否定前缀 U 对局部校正、曲率状态或路径权重的价值。

## 7. RF02：GR 缺失结构和局部信号质量

### 7.1 RF02a_gr_missing_geometry_v1

只从隐藏段原始 GR 是否缺失的 mask 构造 9 列：

| 层级 | 特征 |
|---|---|
| 当前缺口 | 缺口长度、距左/右最近实测点、缺口内相对位置 |
| 局部窗口 | 50/100/200 ft 中实测 GR 比例 |
| 整井 | 隐藏段实测率、最长缺口 |

正式五折：14.7982 / 14.1697 / 15.0079 / 16.2291 / 16.7621；pooled 15.422823，比 B00 好 0.630949。

为判断收益是否真来自“缺口位置”，又跑了三类归因实验：

| 实验 | 方法 | pooled/折结果 | 解释 |
|---|---|---:|---|
| mask-shift null | 每井循环错移缺失 mask，再计算同维9列 | 15.587805 | 错位特征仍比B00好0.465967 |
| well-only | 只保留整井实测率和最长缺口 | f0 15.1134，f1 14.4109 | fold1反向 |
| centered-local | 只保留50/100/200局部实测率减整井实测率 | 16.025638 | 只比B00好0.028134 |

真实 mask 只比错位 mask 再好 0.164982，95% 区间跨零；在真正缺 GR 的行上两者仅差约 0.0012。

因此：RF02a 的整组特征确有约 0.63 ft 提升，但大部分可能来自井、区域或数据采集模式代理，尚不能证明模型真正学会了“当前缺口中哪个位置不可信”。

### 7.2 RF02b_local_gr_quality_v1

在原始非缺失 GR 上计算 50/100/200 ft 中心窗口的 MAD 和 variance，共6列。fold 0 为 16.627748，只比 B00 好 0.048630，停止。

尚未测试的 GR 质量信息仍很多：一/二阶差分 MAD、分位距、尖峰比例、平线比例、自相关、局部趋势、前后分布漂移。由于已有简单统计几乎无收益，这条线优先级应低于 PF-centered 局部对齐。

## 8. RF03/F03a：Typewell 在可见前缀上是否可信

### 8.1 RF03_D0_prefix_alignment_v1

这是合法正对照，不训练模型。把水平井可见前缀 GR 与 Typewell 在 TVT_input + offset 处的 GR 对齐，比较 offset = -20/-10/0/+10/+20 ft。

| 指标 | 全前缀 0-offset 胜率 | 最后1000ft 0-offset 胜率 |
|---|---:|---:|
| NCC | 99.09% | 97.54% |
| affine MAE | 97.28% | 90.04% |

全前缀 0-offset NCC 中位数约 0.8129，±10 ft 错位约 0.54–0.55；尾1000 ft 0-offset约0.741，错位约0.15–0.20。

这个诊断明确说明 Typewell GR 信号存在。后续模型失败不能解释成“Typewell 完全无用”。

### 8.2 F03a_typewell_prefix_reliability_v1

把 RF03 压成每井 18 个常数，复制到隐藏行：

- 全前缀和尾1000 ft各保存：0-offset raw NCC、affine MAE、有效点数/比例、NCC margin、MAE margin；
- 再保存尾部减全前缀的六个差值。

fold 0 为 14.863136，改善 1.813241；fold 1 为 15.580803，反向 1.293614，停止。

### 8.3 F03a_multiscale_prefix_reliability_v2

新增9列：raw及2/5/10/20 ft平滑 NCC、affine median AE、导数NCC、有效点数和比例。

fold 0 为15.750568，改善0.925809；fold 1为15.428975，反向1.141787，停止。

两版共同问题：它们大多是整井常数，只描述“这口井整体是否像 Typewell”，没有告诉模型“隐藏段当前位置应向哪个 TVT offset 修正”。尚未实现 affine a/b、连续 block 稳定性、局部 offset 漂移、最后200ft与完整前缀的差异。

## 9. F03b：Typewell offset 得分面

### 9.1 实际跑过的版本

实际搜索中心是恒定 U 路径，不是 PF：

\[
TVT_i^{center}=TVT_{anchor}-(Z_i-Z_{anchor})
\]

在 -40 到 +40 ft、步长2 ft上搜索；水平井和Typewell都只做10 ft平滑；每行使用101 ft窗口NCC。新增12列：最佳/第二offset与NCC、峰间距、峰差、soft offset均值/标准差、熵、主峰质量、有效点数/比例。

结果：fold 0 为16.075058，改善0.601319；fold 1为14.371267，反向0.084078，停止。N06把同一组特征加到C01后，fold 0为11.795128，比C01反向0.086176。

### 9.2 为什么这个负结果不能关闭 F03b

fold 0 的真值相对不同中心：

| 搜索中心 | 真实偏移中位数 | P90 | 真值落在±40ft |
|---|---:|---:|---:|
| 恒定 U | 82.85 | 190.38 | 25.61% |
| PF ANCC | 3.82 | 21.87 | 98.53% |
| Beam mean | 7.58 | 22.92 | 99.33% |

多数真值根本不在实际 F03b 的候选窗内，GR 评分器再好也无法找到答案。

路线图中真正未完成的版本应当围绕 PF/Beam，并加入 raw/2/5/10/20 ft多尺度NCC、robust/affine MAE、导数NCC、峰宽、尺度一致性、最长有效段和有效块数。

隐藏真值 oracle 进一步说明其表示空间：

| PF-centered offset网格 | oracle RMSE |
|---|---:|
| ±20ft，步长2ft | 5.9701 |
| ±40ft，步长2ft | 2.4013 |
| ±80ft，步长2ft | 0.5718 |

这些是读取真值选 offset 的不可提交上限，但证明“PF中心附近的局部修正”有足够覆盖，是当前最清楚的未完成突破口之一。

## 10. F04：branch-aware self-template

F04只用当前井可见前缀构建 GR(TVT,方向,访问段) 模板：

- TVT bin宽0.5 ft；
- 按TVT上升/下降切连续段；
- 保存每个bin的GR中位数、MAD和支持量；
- 在恒定U中心附近测试 -20/-10/0/+10/+20 ft；
- 输出覆盖标记、距可见TVT范围、同/反方向支持数、访问次数、模板GR及误差、101ft NCC、最佳offset、最佳误差和score gap，共12列。

正式门槛结果：fold 0为14.832230，改善1.844147；fold 1为14.652680，反向0.365491，停止。

artifact中还有额外 folds 2–4：15.626064 / 16.180114 / 16.574758。合并五折约15.590745，比B00好0.463027，但这不能事后把原实验改判为晋级。

重要边界：F04不读取训练集中同一口井的完整TVT，也不读取当前井隐藏TVT。它只用测试时可见的当前井前缀，因此是合法的前缀自校准，不属于历史“训练测试同井重合后读取完整标签”的覆盖bug。

它确实依赖隐藏段GR能在前缀TVT/GR模板中获得足够覆盖，但这只是需要验证的分布适用性，不是泄漏理由。当前版本原门槛未晋级，只能否定这一版分段、中心路径和评分器，不能排除更好的self-template实现。

## 11. F05：物理候选与PF内部不确定性

### 11.1 F05a_precomputed_candidate_geometry_v1

这是最接近路线图原定义的“候选分布几何”。从15条候选路径计算：

- 行级中位数、IQR、MAD、跨度、最大间隙、典型分离、尾部分离；
- PF距候选中位数、Beam组与Scale组差、PF seed std、PF与Z差、scale score std、跨度增长；
- 井尾候选中位数/IQR/MAD/跨度/最大间隙。

fold 0为12.749505，改善3.926872；fold 1为15.134127，反向0.846938；额外fold 2为15.041948。说明摘要丢失了候选路径本身的很多信息。

它也没有真正实现模式数、模式质量、函数路径成对距离、medoid距离和late divergence fraction。

### 11.2 F05a_direct_physical_candidates_v2

不再只给摘要，而是直接输入24列候选/分数：

| 家族 | 特征内容 |
|---|---|
| PF 4列 | pf_ancc_delta、pf_ancc_std、pf_z_delta、pf_vs_z |
| Beam 10列 | 7条不同约束Beam，以及beam_mean/std/median |
| self-NCC 9列 | sc8/15/25路径与分数、consensus、ensemble、trust |
| hybrid 1列 | Beam与self-template路径加权 |

五折12.864131，相对B00改善3.189641。但旧Notebook的两个Numba PF内核没有真正固定内部随机状态，所以该24列缓存不能严格重建，只能作为参考。

### 11.3 F05a_deterministic_candidates_v1 / C01

重新生成完全同样的24列，并显式固定ANCC PF seed 42、Z PF seed 43。结果12.930691，只比旧随机缓存差0.066561，成为当前正式C01。

机制证据：把24列候选在每井内联合错位后，同一已训练模型从12.930691退化到15.094565，说明逐行路径位置确实包含真实信息。

### 11.4 当前C01究竟在用什么

五折平均LightGBM gain importance按家族聚合：

| 家族 | gain占比 |
|---|---:|
| B00基础12列 | 36.95% |
| PF 4列 | 36.80% |
| Beam 10列 | 26.04% |
| self-NCC + hybrid | 0.21% |

树重要性不是严格因果消融，但足以说明当前主收益来自PF和Beam，不是self-template。17条实际路径单独评分时：

- pf_ancc_delta：14.2433；
- pf_z_delta：17.3684；
- Beam家族最佳约15.7736；
- self-template/hybrid路径均极差，且逐井oracle从未把它们选为最佳。

所以当前C01包含合法的当前井前缀self-template，但模型几乎不使用。可以补一个PF+Beam-only正式消融来做候选家族归因和简化基准；这不是清除“训练—测试同井覆盖bug”的必要步骤。在正式消融前，也不能只凭importance宣称它完全无影响。

### 11.5 F05b_internal_stats_v1

对确定性ANCC PF增加10列归一化内部统计：当前ESS比例、有效更新ESS均值/最小值、低ESS比例、重采样比例、权重塌缩比例、平均log-likelihood gap、归一化熵、距上次有效更新比例、有效更新比例。

相对B00：fold 0为14.771314，改善1.905063；fold 1为14.584466，反向0.297277，停止。

加到C01成为N03后完成五折，最终12.957757，比C01差0.027066。结论是：当前10个PF内部退化统计没有提供稳定的条件增量。

## 12. F06：可见前缀伪隐藏回测

F06从自然可见前缀制造6个伪切点：50%/65%/75%比例cut，以及250/500/1000 ft horizon cut。每个cut都重新隐藏cut后的TVT_input，再重算候选，避免用完整前缀回头评分。

五个候选家族为carry、geometry、PF、Beam和所谓typewell。每个cut × family保存RMSE、相对carry/PF gain、rank和coverage，再对每个family聚合中位gain、最差gain、gain标准差、gain随实际horizon的斜率；另加rank相关和winner稳定性，总计174列。

结果：fold 0为13.966823，改善2.709554；fold 1为15.543152，反向1.255963；额外fold 4为16.549314。停止。

两个关键问题：

1. F06只是把174个历史摘要交给LightGBM，并没有用这些伪holdout直接估计候选组合权重或PF残差曲线；
2. 代码中名为typewell的家族实际映射到sc_ens_d，而sc_ens_d是当前井self-template，不是真正Typewell路径。

因此F06不能证明“Typewell历史可靠性无用”，也没有真正否定“用多horizon前缀回测估计候选权重”的思路。

## 13. F07R：严格折外邻井相对 U

F07R是唯一正式使用其他训练井真值的路线，采用严格outer-fold缓存：排除目标井、同pad井和整个验证fold。

方法：

1. 对邻井构造U=TVT+Z并按25 ft下采样；
2. 计算完整轨迹最近距离、方位差、平行重叠、顺/横轨距离和heel/toe距离；
3. 只保留方位差≤45°、平行重叠≥500 ft的邻井；
4. 用目标井最后1000 ft可见前缀拟合U_input-U_neighbor=a+b·s；
5. 最多聚合8口邻井。

新增10列：邻井相对U先验、坡度、曲率、MAD、最近轨迹距离、方位差、平行重叠、支持井数、有效权重、邻井分歧。

结果：fold 0为15.437243，改善1.239134；fold 1为15.097641，反向0.810452，停止。surface lineage审计通过，说明失败不是直接读取验证surface造成的。

当前只能否定严格outer-fold top-8邻井、当前筛选/映射/线性前缀校准这一版，不能否定所有空间相对结构。但这条线成本高、现有证据弱，优先级应低于修复PF和F03b。

## 15. 当前候选池和轨迹表示的只读 oracle

以下全部读取隐藏真值，只用于判断表示能力，不能作为模型成绩。

### 15.1 17条当前候选路径的上限

从确定性候选缓存重算：

| oracle | RMSE | 含义 |
|---|---:|---|
| 每井从17条路径选一条 | 9.07436 | 已知整井真值后选最佳候选 |
| 上述加入carry | 9.03994 | 多一个末值延续候选 |
| 每行独立选最近候选 | 6.98006 | 每行偷看真值硬选 |

1. 只做更强top-1排序不可能达到5，因为逐行硬选都只有6.98；

每井对PF残差做真值拟合也得到：常数8.9458、线性6.2976、二次5.0388、三次4.2441。PF中心加低阶平滑残差是一个有明确表示空间的方向。

## 16. 当前12.93离5.0有多远

### 16.1 RMSE差不能只看成7.93 ft

平方损失下：

\[
1-\frac{5^2}{12.930691^2}\approx85.1\%
\]

也就是说，要达到5，需要消除当前约85.1%的SSE，不是再提升0.5或1 ft。

### 16.2 误差不是少数尾部造成的

- 68口RMSE>20的井贡献51.10% SSE；
- 最坏100口井贡献60.65% SSE；
- 完美修复最坏68口，整体仍约8.96；
- 仅靠完美修坏井达到5，需要约286口。

所以后续方法必须同时改善大量普通井和困难井，单独做异常井门控不够。

### 16.3 当前候选生成本身也不足

当前17条路径的逐行硬选oracle为6.98、逐行凸包oracle为6.17，仍高于5。这意味着：

> 在现有候选路径不变时，仅靠候选排序、置信度或硬切换，理论上也很难达到目标。

必须至少增加更准确的候选支撑，或允许对PF残差做连续局部修正。

## 17. 历史10.x和“强队CV<5”能否比较

| 数字 | 来源和问题 | 能否直接比较 |
|---|---|---|
| 旧LGBM-3 10.4733 | ordinary well GroupKFold；空间/KNN未按outer fold重建 | 否 |
| 旧Ridge stack 10.4197 | 多模型；stacking不严格nested | 否 |
| 旧model package post 10.6702 | 多模型+TCN+后处理；空间imputer风险 | 否 |
| 旧报告PF 10.7321 | 本地没有对应预测/metrics artifact | 尚未核验 |
| 旧报告best-of-24 7.7697 / top10 8.7483 | 旧隐藏真值oracle，本地无当前CV artifact | 否 |
| 强队CV<5 | fold、mask、邻井、训练测试同井重合和Typewell分组规则未知 | 目前未知 |

当前spatial-pad CV比普通well GroupKFold更严格：旧fold中大量验证井在1000/2500 ft内仍有训练邻井，而当前按中位XY的1000-unit连通pad不跨折。

另外，当前主CV也并非“新Typewell严格泛化”：773个Typewell文件归并裁剪关系后只有约54个模板，40/54个模板仍跨主fold；每折大多数验证井在训练集中仍有同模板。Typewell fingerprint strict CV尚未真正运行。

因此应把“强队5”当作方向目标，而不是在协议未知时认定我们纯算法落后7.9 ft。首先要确认标尺。

## 18. 数据血缘和实现偏差清单

这些问题会直接改变对实验的解释：

1. **B00实际没有PF/Beam。** 路线图文字与feature_list不一致。
2. **当前C01不是历史多seed selector PF。** 它用的是另一套单次PF候选。
3. **当前C01含合法的前缀self-template。** sc8/sc15/sc25/sc_cons/sc_ens/sc_trust和hyb只依赖本井可见TVT_input/GR，不是训练—测试同井覆盖bug；不过gain仅约0.21%，尚缺正式家族消融。
4. **实际F03b中心错误。** 用恒定U而非冻结PF，且没有路线图要求的多尺度MAE/导数/支持量。
5. **F06所谓typewell实际是self-template。** 因此不能把F06失败归因于真正Typewell候选。
6. **N04不是严格复用standalone RF02b。** N04额外加入3个observed_count。
7. **F05a胜出的是直接候选路径，不是路线图原候选几何摘要。** 两者应分开解释。
8. **F04、F05a precomputed、F06有额外折artifact但registry未登记。** 原门槛决定保持不变，额外结果只作诊断。
9. **Typewell fingerprint strict CV未执行。** 仍不知道重复模板对主CV贡献多少。
10. **surface近零恢复不是合法突破。** lineage审计显示surface几乎是TVT和Typewell marker派生标签；测试无surface。

## 19. 已经可以相信的研究结论

### 19.1 高可信

- 物理候选路径是目前唯一稳定的大信号，C01五折均改善。
- 原始逐行GR在已有PF/Beam后几乎没有直接树重要性；GR主要应通过对齐和路径生成发挥作用。
- Typewell在真实可见TVT位置有强对齐信号，RF03-D0正对照明确通过。
- 固定前缀坡度不能无界外推自然长隐藏段。
- 当前PF内部ESS/熵等10列没有C01条件增量。
- 当前17路径top-1/逐行硬选支撑不足以达到5。

### 19.2 中等可信

- GR缺失模式有约0.6 ft信息，但大部分可能是井/区域代理。
- Huber前缀倾角有约0.8 ft边际信号，但与物理路径结合后的价值未被证明。
- self-template是合法当前井前缀信号；当前版本有小幅边际信号，但C01几乎不使用，值得在统一PF中心和统一评分器下重新比较。
- 当前严格邻井top-8实现没有稳定价值，但不能关闭所有相对空间结构。

### 19.3 不能成立

- “Typewell没有用”。正对照明确相反。
- “F03b已经失败”。真正PF-centered版本尚未做。
- “我们已经复现PF 10.7”。本地没有可比artifact，当前PF也不是那一版。
- “多加候选可靠性常数就能接近5”。现有条件组合没有证据支持。
- “修好几十口最坏井就能到5”。SSE分解明确否定。

## 20. 下一步突破口：按证据和潜在收益排序

### 优先级0：把当前基准归因说清楚

#### P0-A：C01候选家族消融

只保留B00 + PF 4列 + Beam 10列，删除sc系列和hyb。

目的不是判定合法性，而是回答12.93分别有多少来自PF、Beam和当前井前缀self-template。已有importance和oracle表明self-template大概率不是主收益，但仍需正式同折重训确认。历史训练—测试同井完整标签覆盖已经在数据管线层单独关闭，与本消融无关。

#### P0-B：确认强队和历史分数协议

至少确认：fold是否按空间pad、相同Typewell模板是否跨折、是否允许同名井、评价隐藏段长度是否一致、是否只算自然隐藏行。否则5.0不是同一把尺。

### 优先级1：复现真正的多seed selector PF

当前C01漏掉了Notebook中500粒子×128 seeds、按likelihood/scale汇总的selector PF。建议：

1. 固定旧代码和全部参数，不调PF；
2. 在当前773井自然隐藏行上只生成OOF候选路径；
3. 先报告该路径本身的五折RMSE；
4. 再作为一组新增行级特征加入C01；
5. 做井内错位负对照和seed可复现测试。

这是“补回遗漏的已有强候选”，不是搜索PF参数。若它在严格CV仍接近旧10.7，将是目前最大、最直接的提升机会；若失败，也能澄清旧10.x究竟来自宽松CV还是其他模型层。

### 优先级2：真正的 PF-centered F03b_v2

建议围绕pf_ancc_delta和beam_mean_d分别构造局部offset得分面：

- offset至少覆盖±40 ft，2 ft步长；
- raw/2/5/10/20 ft多尺度；
- NCC、稳健MAE、affine MAE、导数NCC；
- 最佳/第二峰、峰差、峰宽、soft offset、熵、尺度一致性；
- 有效点率、最长有效连续段、有效块数；
- 直接生成PF + soft_offset和Beam + soft_offset校正路径，而不只给可靠性摘要。

先做scorer oracle审计：真实offset在GR得分面中的rank、top-k命中率、不同GR缺失率/Typewell模板中的表现。只有GR分数能辨认正确offset，才进入LightGBM实验。

这一方向的依据最强：PF-centered ±40网格覆盖足够，隐藏真值oracle约2.40，而当前F03b因错误中心连答案都看不到。

### 优先级3：补全“候选路径形状”，而不是继续加井级常数

当前N01只用了同一行的族间差，原F05a几何也没有完成路线图中的函数级结构。值得测试：

- 候选路径一阶/二阶导数差；
- PF与Beam分歧从哪一个MD开始增长；
- 后25%/50%路径分歧增长率；
- 整段函数距离和相关系数；
- 模式数、模式质量、medoid及距medoid距离；
- 候选包络是否向单侧持续扩张；
- PF残差相对MD的局部offset、slope和curvature候选。

这些特征应优先生成“可直接使用的校正路径”，其次才是std/entropy等摘要。C01的成功已经表明LightGBM更需要路径位置，而不是只需要不确定性描述。

### 优先级4：利用前缀伪holdout估计低维残差或候选权重

现有F06只生成174个历史分数，没有真正估计权重。表示oracle显示每井候选线性组合可到约3.50，PF残差三次曲线可到约4.24。可做的诊断是：

1. 在多个自然可见前缀cut上重新生成候选；
2. 只用伪隐藏真值拟合非负、和为1、向固定先验强收缩的候选权重；
3. 或拟合PF残差的2–4个低阶系数；
4. 检查这些系数从短horizon到长horizon是否稳定；
5. 把合法前缀估计得到的路径作为一列确定性特征交给唯一LightGBM。

这条线可能触碰当前“禁止output融合/learned trajectory”的合同。实施前必须明确批准；但从达到5的表示能力看，它比继续堆静态特征更符合问题结构。

### 优先级5：Typewell局部可靠性和模板指纹

RF03-D0已证明Typewell信号存在。下一版不应继续使用整井常数，而应保存：

- 连续block的NCC/MAE均值、方差和最差值；
- 局部最佳offset随MD的漂移速度；
- 最近200/500/1000 ft相对完整前缀的可靠性变化；
- affine a/b及校准前后gain；
- 各尺度offset是否一致；
- Typewell模板ID/指纹频次、是否在训练中见过、同模板邻井统计。

同时补跑Typewell fingerprint strict CV。若主CV有效、strict失效，就能明确收益来自比赛内重复模板，而不是全新模板泛化。

### 优先级6：剩余小信号

以下方向可以继续，但不应期望单独把12.93拉到5：

- GR一/二阶差分、尖峰、平线、自相关和分布漂移；
- 显式U change point及变化位置；
- 邻井相对U在Typewell参考系归一化后的重做；
- 困难井门控、GR缺失切片和候选包络外标记。

它们更适合在主路径修正成功后做0.1–0.5 ft级精修。

## 21. 不建议继续消耗时间的方向

- 继续微调50/100/200/500/1000 ft坡度组合；
- 把前缀坡度无界外推到整段；
- 在错误恒定U中心上继续调F03b窗口；
- 继续堆ESS、熵、重采样率等PF内部常数；
- 只用MAD/variance等简单原始GR统计；
- 从现有17条路径中训练top-1硬选择器；
- 在现有sc路径单独RMSE极高的情况下，只微调同一套self-template窗口而不修正中心路径和评分器；
- 在没有严格fold证据时恢复surface/contact或同名井覆盖；
- 围绕fold0反复挑小版本。

## 22. 建议的近期实验顺序

| 顺序 | 实验 | 要回答的问题 | 期望级别 |
|---:|---|---|---|
| 1 | 真正128-seed selector PF只读复现 | 当前项目是否漏掉历史最强PF路径 | 可能是数英尺级 |
| 2 | C01 + multi-seed PF路径 | 单模LGBM能否利用该强候选 | 数英尺或明确否定 |
| 3 | PF-centered F03b scorer诊断 | Typewell GR能否选中真实局部offset | 决定路线生死 |
| 4 | C01 + PF/Beam soft-offset校正路径 | 局部对齐能否稳定降分 | 目标至少1ft级 |
| 5 | C01候选家族消融 | 归因PF、Beam、合法前缀self-template各自贡献 | 机制澄清 |
| 6 | 函数级候选分歧/曲率 | 能否预测路径何时开始走错 | 中等增量 |
| 7 | 前缀估计低维权重/残差系数 | 合法信息能否接近3–5的表示空间 | 需先批准合同边界 |
| 8 | Typewell strict CV | 主CV收益是否依赖重复模板 | 泛化审计 |

## 23. 最终判断

当前实验不是“完全没学到东西”。它已经非常清楚地排除了大量低价值做法，并找到一条稳定主线：PF/Beam候选路径。

真正的问题是，我们目前停在了“把一套较弱的单次PF/Beam候选交给LightGBM”，而没有完成三件更关键的事：

1. 没有在固定CV中复现历史真正的多seed selector PF；
2. 没有围绕正确PF中心做Typewell多尺度局部校正；
3. 没有合法估计低维路径残差或候选软权重。

所以接下来不应再把主要精力放在几十个井级统计特征上。若目标真是接近5，研究重心应转为：

> 先生成覆盖真值的更强路径，再用Typewell GR和可见前缀去估计连续局部修正；LightGBM只负责学习这些路径和修正何时可信。
