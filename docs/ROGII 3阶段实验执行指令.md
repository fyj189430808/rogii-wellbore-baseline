# ROGII 3阶段实验执行指令

做实验必须要快，不做无用的登记和审查，以效率为主，以探索出CV提升的方案为主，每个实验开始前的准备不超过5分钟

## 一、当前结论

当前正式最佳基线保持不变：

```text
P2-P02
balanced_well_5fold_v1
41 列特征
pooled micro RMSE = 10.3057
```

目前已经确认：

1. `GRM01` 全井 GR 自由常数偏移明显失败，停止。
2. `N01m` 邻井平均残差迁移失败，停止。
3. `R01a` 低维残差表示能力很强，但合法系数预测失败，暂时停止。
4. `PFM01` 发现了真正有价值的新候选：
   - 旧五路径 oracle：约 10.3738；
   - 三模式 oracle：约 9.2291；
   - 67.18% 的井上，三模式候选池优于旧五路径候选池。
5. 当前失败点不是候选数量不足，而是无法稳定辨认正确候选。
6. 旧仓库已经证明，普通整井候选排序器、短前缀候选选择和自由 GR 偏移均不可靠。
7. 旧仓库中唯一较有希望的合法路线是：
   - 局部候选成本；
   - 沿井深连续选择；
   - 保守保留原 PF/P2 路径。

接下来禁止继续堆普通井级统计量，也不要重新训练普通整井候选排序器。

# 二、固定实验合同

## 主基线

```text
baseline: P2-P02 原 41 列
CV: balanced_well_5fold_v1
target: TVT - last_known_TVT
model: 原固定 LightGBM
n_estimators: 1734
seed: 29
evaluation: 自然隐藏行
```

## 数据边界

- 影子井继续冻结，禁止打开。
- fold 0 已被用于 PFM01、GRM01、N01m 和大量诊断，不能再作为新路线的主要确认折。
- 新正式实验优先运行 folds 1–2。
- folds 1–2 通过后再运行 folds 3–4。
- fold 0 最后可以补算，但必须标记为探索折。
- 不覆盖任何 P2-P02 和 PFM01 原始产物。

## 统一门槛

folds 1–2：

```text
平均改善 >= 0.15 ft
任一折恶化不得超过 0.15 ft
```

通过后运行 folds 3–4，完整开发集要求：

```text
pooled micro RMSE 改善 >= 0.10 ft
至少 3/4 个确认折改善
井级 bootstrap 95% CI 上界 < 0
P90 well RMSE 不明显恶化
收益不能只来自极少数井
```

# 三、第一优先级：PFM02 三模式完整路径直接进入主模型

## 实验编号

```text
P3-PFM02_direct_mode_paths_v1
```

## 唯一假设

PFM01 生成的低、中、高三条完整模式路径具有真实 oracle 增量。现有 LightGBM 可能像利用 PF、Beam 和五条 PF128 路径一样，直接利用三条模式路径，而不需要先训练井级分类器或硬选择器。

## 特征

基础特征：

```text
P2-P02 原 41 列
```

只新增：

```text
pf_mode_low_delta
pf_mode_middle_delta
pf_mode_high_delta
```

第一版禁止加入：

```text
direction_score
mode_mass
mode_seed_count
mode_separation
p2_position
AUC 派生统计
```

原因：当前真正具有 oracle 价值的是完整路径，不是井级方向分数。

## 执行顺序

1. 检查三条路径缓存与 PFM01 正式缓存逐行一致。
2. 检查三条路径不包含隐藏 TVT 派生量。
3. folds 1–2 正式训练。
4. 若通过门槛，再运行 folds 3–4。
5. fold 0 最后补算，只作探索。
6. 若正式提升，做两种负对照：
   - 每口井内反转三条模式路径；
   - 三条路径在井间确定性错配。
7. 负对照提升必须消失。

## 停止条件

若 folds 1–2：

```text
平均改善 < 0.15 ft
或任一折恶化 > 0.15 ft
```

则停止，不通过调 LightGBM 参数挽救。

# 四、第二优先级：PFM-D02 完整 oracle 阶梯

## 实验编号

```text
P3-PFM-D02_representation_oracle_ladder_v1
```

## 类型

只读 oracle 诊断，不生成正式特征，不训练正式模型。

## 目的

明确下一步瓶颈究竟属于：

1. 三模式聚类损失；
2. 模式中心表示损失；
3. 需要连续混合；
4. 需要分段切换；
5. 128 条 seed 候选本身不足。

## 必须计算

### A. 当前候选 oracle

```text
P2、low、middle、high 每井选一条最佳
```

### B. 三模式固定连续混合 oracle

每口井拟合：

```text
非负权重
权重和为 1
候选为 P2/low/middle/high
```

报告无正则版本和强收缩版本。

### C. 分段模式 oracle

固定窗口：

```text
250 ft
500 ft
1000 ft
```

分别计算：

```text
每块独立选 P2/low/middle/high
加入切换惩罚后的连续分段选择
```

### D. 128 条 seed 路径 oracle

```text
每井从 128 条完整 seed 路径中选一条
```

### E. 模式 medoid oracle

每个模式分别构造：

```text
似然加权中心
逐行中位路径
真实 medoid 路径
```

比较三者 oracle。

### F. 候选包络 oracle

```text
三模式逐行包络
128 seed 逐行包络
```

## 决策规则

### 若连续混合明显优于整井硬选

```text
改善 >= 0.30 ft
```

后续重点做平滑模式权重，而不是分类器。

### 若分段选择明显优于整井硬选

```text
改善 >= 0.30 ft
```

直接进入 MDP01。

### 若 128 seed oracle 明显优于三模式 oracle

说明：

```text
mean + endpoint 的二维聚类损失过大
```

进入 PFM03 形状感知聚类。

### 若 medoid 明显优于加权中心

正式模式候选改用真实 medoid，不再使用算术平均中心。

### 若所有 oracle 都只能接近 9

说明 PF128 候选生成本身开始成为瓶颈，后续优先进入粒子平滑。

# 五、第三优先级：MDP01 离散模式动态路径

仅在 PFM-D02 显示分段选择有明显 oracle 增量后运行。

## 实验编号

```text
P3-MDP01_discrete_mode_dynamic_path_v1
```

## 状态空间

每个井深块只允许四个状态：

```text
P2-P02
low mode
middle mode
high mode
```

禁止自由搜索任意 TVT 偏移。

## 第一版分块

```text
块长 = 250 ft
步长 = 125 ft
```

不同时搜索大量窗口。只有第一版有信号后才测试 500 ft。

## 局部成本

只使用原始观测 GR。

禁止把长缺口中的线性插值 GR 当成完整真实观测。

每个块、每个候选计算：

```text
21 ft 平滑 GR 稳健绝对误差
51 ft 平滑 GR 稳健绝对误差
101 ft 平滑 GR 稳健绝对误差
一阶变化误差
块内相关性
有效原始 GR 比例
Typewell 范围越界惩罚
候选与可见前缀 U 坡度连续性
```

所有 GR 缩放和平移参数只能由当前井可见前缀拟合。

## 动态路径目标

```text
局部候选成本
+ 状态切换惩罚
+ 模式路径位置跳变惩罚
+ 二阶连续性惩罚
+ P2 默认保留先验
```

P2 必须作为安全状态。

只有其他模式在连续多个块中获得明显优势时才能切换。

## 输出

至少生成：

```text
mdp_dynamic_delta
mdp_selected_state
mdp_margin
```

并生成保守融合路径：

```text
mdp_safe_10_delta = 0.9 * P2 + 0.1 * MDP
mdp_safe_25_delta = 0.75 * P2 + 0.25 * MDP
```

融合权重只能在外层训练部分确定，禁止看验证折挑选。

## 正式评价顺序

1. 动态路径自身 RMSE。
2. 保守融合路径自身 RMSE。
3. 通过后再作为一列完整路径加入 P2-P02 主模型。
4. 做 GR 循环错移和块级成本打乱负对照。

# 六、第四优先级：PFM03 形状感知模式聚类

仅在 PFM-D02 显示 128 seed oracle 明显优于当前三模式时运行。

## 实验编号

```text
P3-PFM03_shape_aware_modes_v1
```

## 当前问题

PFM01 每条 seed 路径只压缩为：

```text
平均偏移
末端偏移
```

这会丢失：

```text
前段分叉
中段弯曲
后段回归
局部分支切换
```

## 新表示

将每条 seed 路径在归一化隐藏进度上采样：

```text
32 或 64 个固定点
```

减去 `pf128_scale8` 或 P2 路径后聚类。

第一版固定：

```text
K = 3
```

禁止根据真值选择 K。

## 模式代表

同时生成：

```text
模式真实 medoid
逐行中位路径
似然加权中心
```

通过 oracle 诊断选择一种代表方法，不事后根据正式 CV 选择。

## 统一命名

模式不能按似然质量编号，必须按路径位置命名：

```text
low
middle
high
```

位置排序优先使用：

```text
整段平均相对 P2 偏移
```

并用末端偏移作为次排序条件。

## 输出

```text
shape_mode_low_delta
shape_mode_middle_delta
shape_mode_high_delta
```

随后重复 PFM02 的直接路径入模实验。

# 七、第五优先级：CFGR-D01 独立 GR 分块评分审计

## 实验编号

```text
P3-CFGR-D01_observed_block_candidate_scoring
```

## 类型

只读诊断。

## 目的

当前 PF 候选生成和候选评分重复使用同一份 GR。需要判断不同 GR 区块能否互相验证候选。

## 代理版本

不重新运行 PF，直接使用现有：

```text
P2
low
middle
high
128 seed paths
```

步骤：

1. 仅保留原始观测 GR。
2. 按连续 250 ft 分块。
3. 奇数块和偶数块分别计算候选得分。
4. 检查奇数块的候选排序与偶数块是否一致。
5. 检查两组排序与真实 TVT RMSE 排序的关系。
6. 使用多组确定性循环错移，而不是只做一次 roll。
7. 使用跨井错配作第二负对照。

必须输出：

```text
候选得分与真实 RMSE 的 Spearman 相关
top-1/top-3 命中率
不同 GR 块间排序一致性
正常评分与负对照差值
```

若不同块之间都无法形成稳定排序，不再投入完整交叉 PF。

# 九、第七优先级：PFS01 粒子平滑路径

若 PFM-D02 表明 128 seed 候选池自身已经接近瓶颈，则进入此路线。

## 实验编号

```text
P3-PFS01_fixed_lag_particle_smoothing_v1
```

## 第一版

固定滞后：

```text
250 ft
500 ft
1000 ft
```

当前行的状态不立即冻结，而是使用后续固定长度 GR 再确定较早状态。

输出：

```text
pfs_lag250_delta
pfs_lag500_delta
pfs_lag1000_delta
```

后端不足滞后长度时回退到原 PF。

## 高级版本

保存重采样祖先编号，从末端高权重粒子回溯真实完整粒子轨迹。

该版本用于解决：

```text
每个 seed 输出粒子加权均值
导致两个真实模式被压成不存在的中间路径
```

在祖先回溯轨迹上重新做模式聚类，而不是在逐行均值路径上聚类。

# 十、可做但优先级较低的实验

## UP01：预测路径自身稳健投影

不是预测真值残差，而是对当前预测路径的：

```text
U = TVT + Z
```

做二次或三次稳健投影，再与原路径保守融合。

固定候选：

```text
25% 投影
50% 投影
75% 投影
```

先做路径自身评分。

预期仅为小修正，不应阻塞主路线。

## 邻井信息

禁止再预测：

```text
平均残差
绝对 TVT
完整校正路径
```

邻井只允许作为 MDP01 或候选排序中的弱一致性成本：

```text
候选 U 坡度与邻井 U 坡度差
候选曲率与邻井曲率差
平行重叠区内相对走势差
```

无近邻时必须自然置零。

# 十三、工作方式要求

每个实验必须维护状态：

```text
已设计
已实现
测试通过
只读诊断完成
folds 1–2 完成
folds 3–4 完成
负对照完成
已登记
```

每次实验结束必须写清：

1. 改了什么；
2. 没改什么；
3. 使用了哪些输入；
4. 是否读取隐藏真值；
5. 隐藏真值只用于诊断还是进入正式特征；
6. 相对哪个基线；
7. 哪些折参与了设计；
8. 哪些折是确认折；
9. 能否排除实现错误；
10. 结论能够否定到什么边界。

不要因为某个诊断 AUC 或 oracle 好看，就跳过正式路径自身评价和负对照。

当前最先执行：

```text
P3-PFM02_direct_mode_paths_v1
```

完成后立即执行：

```text
P3-PFM-D02_representation_oracle_ladder_v1
```

其他路线等待这两项结果决定。
